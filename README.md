# Gas Transport Network

Консольное приложение на **C++** для моделирования сети газотранспортной системы — совокупности труб и компрессорных станций (КС), соединённых в направленный граф.

Помимо CRUD-операций над объектами, программа реализует **три классических графовых алгоритма** на собственноручно построенном графе:

- **Топологическая сортировка** с проверкой на цикл (DFS)
- **Алгоритм Дейкстры** — поиск кратчайшего пути между двумя КС, веса рёбер — длины труб
- **Алгоритм Форда-Фалкерсона** — поиск максимального потока в сети (BFS для поиска увеличивающего пути)

---

## Доменная модель

| Сущность   | Класс      | Описание                                                               |
| ---------- | ---------- | ---------------------------------------------------------------------- |
| Труба      | `Truba`    | Имя, длина, диаметр (500/700/1000/1400), флаг ремонта, флаг «свободна» |
| КС         | `CS`       | Имя, число цехов, число работающих цехов, эффективность, входы/выходы  |
| Соединение | `Truba_CS` | Направленное ребро: `id_entry → id_pipe → id_outlet`                   |

Сеть — это набор `Truba_CS`, формирующий ориентированный мультиграф, где вершины — КС, рёбра — трубы. Одна труба может быть использована только в одном соединении (контроль через флаг `free`).

Бизнес-правила, заложенные в логику соединений:

- Труба должна быть свободной (`free == 1`)
- КС не может быть одновременно входом и выходом одного и того же ребра
- Каждая КС суммарно поддерживает не более 2 подключений (`id_input + id_output`)
- При соединении проверяется совместимость диаметра трубы; если подходящей нет — программа предлагает создать новую с автоподстановкой нужного диаметра

## Возможности

### Управление объектами

- Добавление труб и КС с валидацией ввода (длина, диаметр, число цехов, эффективность)
- Просмотр всех объектов и связей
- Сохранение/загрузка состояния в текстовый файл

### Фильтры

**По трубам:**

- По подстроке имени
- По флагу ремонта
- Все

**По КС:**

- По подстроке имени
- По проценту неиспользуемых цехов: `< n`, `= n`, `> n`
- Все

После применения фильтра группу объектов можно **массово редактировать** (переключать флаг ремонта у труб / менять число работающих цехов у КС) или **удалять** — при удалении автоматически разрываются связанные соединения и освобождаются связанные трубы.

### Графовые операции

- Построение соединений между КС с проверкой бизнес-правил
- Топологическая сортировка: выводит порядок вершин или сообщает о наличии цикла
- Кратчайший путь по Дейкстре между двумя КС (вес — длина трубы)
- Максимальный поток по Форду-Фалкерсону между источником и стоком

### Логирование

При запуске создаётся файл `log_<дата>_<время>` — туда дублируется ввод пользователя через перенаправление `cerr`. Удобно для отладки и воспроизведения сессий.

## Сборка и запуск

### Visual Studio (Windows)

1. Открыть `lab1.sln` в Visual Studio 2022.
2. Выбрать конфигурацию `x64 / Debug` или `x64 / Release`.
3. **Build → Build Solution** (`Ctrl+Shift+B`).
4. **Debug → Start Without Debugging** (`Ctrl+F5`).

> Требуется компилятор с поддержкой C++20 (MSVC 19.30+ из VS 2022) — из-за `std::format`.

### Командная строка (g++ ≥ 13)

```bash
g++ -std=c++20 -O2 main.cpp Truba.cpp CS.cpp Truba_cs.cpp -o gas_network
./gas_network
```

## Алгоритмы — детали реализации

### Топологическая сортировка

Классический DFS со стеком результата. Параллельно вызывается `isCyclic` — отдельный обход с массивом `recStack` для обнаружения обратного ребра. При найденном цикле выводится предупреждение, иначе печатается порядок вершин.

### Дейкстра

Реализация на `priority_queue<pair<int,int>, vector<...>, greater<>>` (min-heap). Вес ребра — длина связанной трубы (`Truba::lenght`). Расстояние хранится прямо в поле КС (`CS::shortest_path`), инициализируется `numeric_limits<int>::max()`. Завершается раньше, если извлечён конечный узел.

### Форд-Фалкерсон

- Из списка рёбер строится матрица пропускных способностей `Rgraph[V][V]`, где пропускная способность — длина трубы.
- BFS (`bfs`) ищет увеличивающий путь от источника к стоку в остаточной сети.
- Для каждого найденного пути вычисляется минимальная пропускная способность вдоль него, обновляется остаточная сеть, накапливается максимальный поток.
- Остановка — когда BFS больше не находит путь от источника к стоку.
